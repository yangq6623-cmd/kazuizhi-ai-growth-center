# R8-22 7×24 自治运行收口版 — 方向锁定

## 1. 最终产品思想（不可漂移）

卡嘴子 AI 的最终目标不是“功能很多的后台”，而是一套 **7×24 小时持续运行、持续学习、持续优化、持续推广的 AI 自动运营系统**。

老板日常只做四件事：
1. 给经营目标和方向；
2. 查看真实结果；
3. 必要时调整优先级；
4. 只处理必须真人介入的授权、高风险和不可逆事项。

其余工作必须尽量由系统自行闭环：

`老板目标 → Command → Mission → Controller Plan → Task → AI员工/模型/工具执行 → Receipt/Evidence → 真实结果 → 学习/复盘 → 下一轮任务`

这是一条 **事件驱动自治主线**，不是“打开页面、手工点击按钮、跑一轮”的页面驱动工作流。

## 2. 三层角色边界

### 老板
- 决定目标、方向和经营边界。
- 不负责日常任务拆解、排队、跨模块搬运状态。
- 不应因为可选社媒账号离线而被迫介入 SEO/GEO 核心工作。

### ChatGPT / Controller
- 是总大脑和调度决策层。
- 读取真实数据和 Receipt/Evidence。
- 形成 Mission、优先级、Controller Plan 和下一轮动作。
- 判断有效/无效策略并持续调整。
- Controller 的确定性安全编排只负责保证任务不断线，不取代 ChatGPT 的经营判断。

### AI 员工 / 云模型 / 本地模型 / 工具
- 是执行层。
- 豆包和本地模型可用于分析、生成、预检、QC、辅助决策。
- 本地/普通云模型输出不得冒充正式 GEO A/B Evidence。
- 每项执行结果必须写回真实 Receipt；失败和阻塞必须可见。

## 3. 现有能力全部保留，不推翻重做

R8-22 是“控制平面收口”，不是重新开发 SEO/GEO。
以下能力必须继承并继续通过回归门禁：
- AI 员工、每日排班、自主学习；
- 豆包云模型、本地模型、模型路由；
- SEO 机会/内容/QC/公网页面/搜索提交/索引与排名监测；
- GEO Phase 1/2/3、1→3→10→50、A/B Evidence、Before/After；
- Remote Agent、公网发布器、百度/Bing/Google 连接；
- 统一连接路由矩阵；
- 经营数据、历史审计、Receipt/Evidence Ledger；
- 24h 防休眠、线程隔离、心跳、失败恢复、熔断；
- 内容生产、视频/GPU、社媒分发等已有执行能力。

## 4. R8-22 只解决 8 个收口问题

1. **Command → Mission 自动接管**：最新已验证老板 Command 自动成为当前 Mission，不再显示旧 Mission 掌权。
2. **Mission → Controller Plan 自动生成**：老板已下目标后，不允许再出现“等待 ChatGPT 下 SEO/GEO 计划”的死锁。
3. **当前 Mission P0 优先级**：当前 Mission 优先，历史积压不得淹没新目标；历史数据不删除。
4. **统一真实状态**：老板监控、AI 决策、执行中心、SEO/GEO 使用同一当前 Mission/Command 语义。
5. **实时事件流**：老板能看到“刚完成什么、正在做什么、下一步是什么”。
6. **待我处理只保留真人事项**：资金、验证码/实名/人脸、核心账号授权、不可逆高风险操作；可选社媒离线只延后该渠道。
7. **历史积压降级**：旧任务降为 backlog，不改写原始结果、不抢当前 Mission 执行权。
8. **版本与状态收口**：R8-18/R8-19 历史账本保留审计价值，但当前执行权明确显示为 R8-22 自治主线。

## 5. 真值红线

- 本地任务 completed ≠ 公网发布成功。
- 公网页面存在 ≠ 搜索引擎已收录。
- 已提交 URL ≠ 已收录/排名。
- 豆包 API / 本地模型输出 ≠ 正式 GEO Evidence。
- 正式 GEO 只能由真实外部 AI/浏览器或满足 Truth Gate 的正式验证路线产生 A/B Evidence。
- 曝光/点击/咨询/任务/订单必须来自真实数据源；不得用模拟值补齐。
- 财务、付款、退款、提现、结算、赔付、改价等真实资金动作永久不自动执行。

## 6. 7×24 运行策略

- 主调度持续运行；Windows 防休眠和异常恢复沿用 R8-20。
- 当前 Mission P0 每轮采用有上限的批处理，避免单个 Mission 阻塞心跳。
- 历史 backlog 每轮只允许少量后台推进，不能抢占当前 Mission。
- 每 15 分钟生成一次阶段性 Receipt，汇总真实任务变化、阻塞和下一步。
- 官网 SEO/GEO 核心链路优先；抖音/小红书/视频号等可选渠道未登录时标记 deferred，核心 Mission 继续。
- 真实外部平台验证码、OAuth/权限、风控门槛只暂停对应通道。

## 7. 发布后的实机验收标准

### 快速验收
老板只下达一次目标：
- ≤15 秒：新 Command 成为当前 Mission；
- 自动出现 Controller Plan；
- 不需要第二次点击“去 SEO/GEO 处理”；
- 当前 Mission 的后续到期任务进入 P0；
- 旧 backlog 不被重新绑定；
- 可选社媒离线显示 deferred，不成为核心阻塞；
- 实时事件流持续更新；
- 约 15 分钟出现第一份阶段 Receipt。

### 连续运行
- 先完成 2 小时实机验收；
- 再完成 24 小时无人值守；
- 最后完成 7 天连续运行。

验收重点不是页面数字漂亮，而是系统能否在没有人工连续点击的情况下，持续产生真实任务、真实执行、真实发布/提交/验证回执，并根据结果进入下一轮。
