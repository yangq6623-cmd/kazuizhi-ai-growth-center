# 卡嘴子 GEO 2.2.2.807 一次性修复交接与现场验收

## 背景
#803 安装成功，Evidence 历史50/50及Receipt可部分读取，但 Chrome 2.2.2.806 的豆包正式采集任务出现 `agent_response_timeout`。真实 Chrome 页面显示待发新问题仍停留在输入框，页面回答是上次电视维修对话；不得将旧回复当作新回答。部分本地 Evidence API/心跳超时可能独立存在，不能以本次扩展补丁宣布全局修复成功。

## 本轮目标
确保“真实问题已发送 → 新回答稳定 → 保存真实Receipt”后才记正式 Evidence；失败不二次发送，不重复发布；独立心跳继续运作。

## 主要修改
- `05_V2.0.0_Source/browser_extension/kazuizhi_geo/content-agent.js`：限制豆包发送控件在当前输入框邻近区域；确认新问题回显且输入框已清空/替换，否则 `question_not_submitted`。采集时检查已确认发出的同一问题执行记录，禁止使用未确认或无记录的旧回答。
- `05_V2.0.0_Source/browser_extension/kazuizhi_geo/service-worker.js`：豆包执行改为 `kz-start`、`kz-capture` 分段读取，等待上限180秒。页面跳转时仅重试读取，不重发问题。失败按原服务端门禁写执行错误，不写成功Receipt。
- Chrome扩展：`2.2.2.807`，沿用60秒独立轻量心跳。
- `04_Build/v2/test_geo_extension_807.js`：模拟未发送、旧问题、已确认发送、成功回答及Receipt真实性；原 #803 兼容测试保留。
- `.github/workflows/build_v2_enterprise_beta.yml`：Windows完整回归后同时生成安装包及独立Chrome扩展ZIP。

## 限制
不得清空历史 50 问、修改真实外部AI记录、自动重复提问或自动增加发布。站点 `SUBMITTED` 不等于 `INDEXED`；页面就绪 `ready` 不等于 Evidence；历史正式50/50不是本轮新增。无人工平台登录不得伪造 A/B 证据。对回答未发、超时或认证失败必须保留失败原因。

## 现场安装与回滚
1. 先备份 #803，退出运行程序，再使用后续GitHub正式成功构建的完整安装包覆盖；构建号以对应GitHub Actions为准，不以历史EXE内部R8-23文件名判断。
2. Chrome 打开 `chrome://extensions`，先关闭2.2.2.806，再解压并加载2.2.2.807（含 `manifest.json` 的目录）。
3. 更新扩展后**刷新已打开的豆包、抖音、千问、DeepSeek和360页面**，避免旧内容脚本留在原标签页。
4. 只让系统领取一条正式测试任务，不连续点击“立即运行一轮”，观察新问题是否真正显示在聊天记录中、输入框清空、同一个任务仅有一条Receipt。
5. 对照后端健康接口、浏览器心跳时间和原始Evidence/Receipt编号；检查24h、72h、7天复测不要重复计数。
6. 如出现问题：停用2.2.2.807，启用2.2.2.806，并恢复 #803 备份；保留日志/Receipt，不删除账户数据。

## 验收标准
- 真实Chrome中豆包新问题已提交且有相同问题完整新回答；严禁采旧回答。
- 未实际发送则明示 `question_not_submitted`，无正式Receipt，不重复发送。
- 发生登录障碍或采集超时后能退出当前任务并记录失败，不堵塞全局任务；心跳仍定期上报。
- 官方正式Evidence接口可连续读取原始问题、回答、平台、时间、来源URL、引用URL和Receipt，不以缓存伪装新增。
- 站长抓取/收录、官网AI引用和咨询转化依真实外部回执分开统计。
- CI通过只证明模拟和安装回归；**本机真实问答验证完成后**方可确认最终闭环通过。
