## 1. 我们做这个系统的核心理念

### 1.1 增长第一

系统第一职责是真实增长：获客、有效曝光、品牌知名度、信任、咨询、需求和真实转化。不是以“发了多少内容”“跑了多少任务”作为唯一成功标准。

### 1.2 真实数据第一

公开搜索 / 联想 / 市场信号只能作为需求线索；小程序访问、咨询、维修需求、个人任务、订单、真实师傅/团长供给没有接入时必须明确显示“未接入/数据不足”，不能用 0 或模拟数字冒充经营成果。

### 1.3 数据闭环

标准闭环：

`本地 Agent → 上报 → 主控 AI 分析 → 今日复盘 / 明日计划 → 白名单低风险指令 → 本地 Agent 执行 → 审计 / 回执 → 再上报`

系统价值不只是“生成内容”，而是能持续看数据、判断市场、调整重点、执行低风险动作、保存结果并复盘下一轮。

### 1.4 长期记忆和实验

自主学习的准确含义不是基础模型自行重新训练，而是：

`长期记忆 + 市场信号 + 实验记录 + 策略评分 + 真实经营反馈`

持续改变下一轮运营和验证策略。成功、失败、无新增都必须保留，避免版本升级后失忆或反复浪费时间。

### 1.5 Human on Exception

老板不应该每天手动点扫描、调关键词、搬文件、做报表。理想状态是电脑开机后系统自动恢复运行；老板想看结果时只需问“今天怎么样”。只有验证码、实名/人脸、安全挑战、重大投诉、资金等必须人工的例外才提醒老板。

### 1.6 产品事实约束增长

AI 必须先理解卡嘴子真实产品能力，再决定怎么推广。不能为了转化夸大未开放能力；必须区分“已确认可推广能力 / 条件开放 / 暂不能宣传”。

### 1.7 安全分层

计划层不等于执行层。主控计划只描述“怎么看、明天优先什么”，执行必须经过低风险白名单。本地 Agent 对非白名单动作拒绝并审计。

支付、退款、改价、补差价、结算、提现、充值、补贴、赔付、佣金打款等任何真实资金结果变更，AI 永久无执行权限。

### 1.8 最终产品化

先用卡嘴子跑出可核验的 30 天、周度、月度真实增长案例；证明 AI 能理解产品、发现市场、分配增长重点、持续实验、保存失败经验并优化下一轮。

之后把底层能力抽象成通用“AI 自主增长运营系统”，可切换到本地店铺、小程序、软件、品牌等项目工作区。每个项目保存独立的市场记忆、客户问题、渠道表现、实验、成功/失败经验，底层增长能力复用。

## 2. 最终方向与阶段路线

1. **卡嘴子真实样板**：围绕涟水 / 淮安把“本地维修 + 个人任务发布”双增长跑通，形成真实增长曲线、30 天案例、周报、月报和实验记录。
2. **真实经营闭环**：接入小程序访问、需求、订单、用户、师傅/团长供给等只读经营数据，从“公开需求信号驱动”升级到“真实转化结果驱动”。
3. **自主运营闭环**：主控 AI 每日复盘、次日计划、低风险任务调度、本地 Agent 执行和结果回流，形成可解释的自动运营、失败淘汰、成功放大。
4. **渠道与区域扩张**：SEO/GEO、内容资产、师傅招聘、区域开城、渠道归因，沉淀“地区 × 服务 × 问题 × 真实案例”的长期增长资产。
5. **通用产品化**：形成多项目工作区和可复用增长底座。

---

## 3. 长期角色分工

- **主控 AI**：看数据、发现问题、判断市场、制定日/周/月计划、下达低风险增长指令、复盘失败策略、规划系统优化。
- **本地 Agent / 增长运营中心**：全天运行、采集公开市场信号、执行白名单低风险动作、保存数据、上报状态、记录审计。
- **老板 / 用户**：开机、看结果、提出新想法；处理验证码、实名/人脸、安全验证、资金和重大例外。
- **平台后台客服**：客户进入正式订单后处理价格、付款、退款、售后和资金争议。

## 5. 功能恢复状态码

- **A**：R3 已完整存在且可运行 → 保持，不重写。
- **B**：R3 有入口 / 界面，但功能不完整 → 补后端、数据、动作和详情。
- **C**：R3 完全缺失 → 从历史稳定版本恢复。
- **D**：功能存在，但真实数据接口未接 → 接真实只读经营数据并保持真实性标识。
- **E**：旧功能可用但架构需要升级 → 先保持兼容，再渐进重构，不能先删后补。

## 7. 增长策略与产品边界

### 市场

- 正式开发市场：淮安市全域。
- 核心主攻 / 样板区：涟水县。
- 之后按真实需求与供给逐步扩展其他县区和江苏其他城市。

### 两个增长飞轮

- 客户：客户 → 订单 → 真实案例 → 搜索/AI曝光 → 更多客户。
- 师傅：订单增加 → 师傅愿意入驻 → 覆盖增强 → 响应更快 → 更多订单。

### SEO/GEO

长期内容骨架：`地区 × 服务 × 问题 × 真实案例`。

持续沉淀官网/H5、地图/商家入口、问答、真实案例、社区/合作节点、师傅服务页、开城页、诊断工具等可长期积累的曝光资产。

### 双增长

本地维修与个人任务发布必须分别建模、分别扫描、分别学习、分别复盘，避免个人任务长期被维修关键词压制。

### 个人任务产品事实

V1.8.5 已确认：

- 用户端可以发布个人任务并自主填写预算。
- 任务类型包括取送跑腿、搬运帮忙、临时安装、代办代购、排队代办、陪同协助、临时用工、其他。
- 当前不能宣传“人人都能直接接单”；接单能力受服务器开关、账号审核、付款状态等实际条件限制。
- 推广必须在真实产品边界内。

## 8. AI 自主学习和主控闭环

### 自主学习的准确含义

不是基础模型自动重新训练，而是：

- 公开市场信号层：学习持续出现的地区、工种、任务类型、问题词。
- 实验层：保留查询→假设→新增证据→新关键词→本轮结果，包括“无新增”。
- 策略层：形成区域/工种/任务类型长期评分。
- 真实经营层：后续用访问、需求、订单、活跃供给等真实数据判断转化。
- 主控 AI 层：读取长期记忆，生成复盘、计划和低风险指令。
- 本地 Agent 层：执行白名单动作、记录审计、回传结果。

## 9. 永久安全边界

### 资金

支付、退款、改价、补差价、结算、提现、充值、补贴、赔付、佣金打款及任何真实资金结果变更，AI 永远无执行权限。

### 核心凭证

AdminKey、支付密钥、数据库密码、核心账号密码/Token 不进入普通升级包、本地上报或增长 AI 执行层。

### 身份和生产安全

验证码、扫码、实名、人脸、安全挑战、重大投诉、不可逆正式生产操作必须人工。

### 合规

不做虚假互动、刷量、假评价、绕过风控、批量骚扰；不采集普通用户私密联系方式。

## 11. 老板最终应该得到什么

### 每天

系统自动扫描、学习、上报、记录异常、生成主控复盘与明日计划；老板只需问“今天怎么样”，并处理少量例外事项。

### 每周

周报要能回答：AI 做了什么、什么有效、什么失败、为什么、下周怎么改。

### 每月

月报要能展示趋势、渠道贡献、客户/师傅增长、转化漏斗、区域表现、成功/失败策略和下月量化目标。

### 每次升级

自动备份、替换、健康检查、失败回滚；老板只验收新功能和历史数据是否保留。

## 12. 正式发布前硬性验收

1. V1.8.5 及之前已验证功能没有减少。
2. 已经接入的功能不能退回成“待接入”。
3. 历史数据、学习记忆、实验、审计、主控计划、30 天案例全部保留。
4. Google Drive 云端桥和低风险指令闭环可用。
5. 真实经营数据未接入项明确标识，不造假。
6. 新 Dashboard 不能只是展示壳，核心入口必须有真实功能或明确状态。
7. 安装包实际安装测试成功，版本、端口、Build Marker 一致。
8. GitHub 同步更新 README / CHANGELOG / VERSION / BUILD_STATUS / 交接文档 / 稳定分支或 tag。

## 13. 交接和记忆维护规则

以后不能只靠聊天记录。每一次重大决定、功能接入、失败经验、版本变化，都必须同时进入 GitHub 交接文档和版本状态文件。

每次重大版本至少记录：

- 为什么改
- 改了什么
- 没动什么
- 测试结果
- 已知问题
- 数据口径
- 权限边界
- 回滚点
- 下一步

后期排错顺序：

1. 先确认实际运行版本、端口和截图，不凭文件名猜。
2. 先读本总纲和对应版本交接文档。
3. 查看 VERSION / BUILD_STATUS / CHANGELOG。
4. 查看 backups、state、daily、ai-center/04_审计日志。
5. 对比 `baseline/v1.9.5-enterprise-r3-20260915`。
6. 必要时回滚；禁止用较早完整文件直接覆盖当前正式版本。
