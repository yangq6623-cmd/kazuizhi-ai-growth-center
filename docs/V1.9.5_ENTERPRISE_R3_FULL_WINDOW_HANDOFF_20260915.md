## 2. 关键过程排序（按发生顺序）

### 阶段 1：Enterprise 初版构建

现象：安装后仍是旧 9 卡片页面。

当时主要怀疑：
- 浏览器缓存；
- 旧包未卸载；
- 新包没有覆盖；
- 安装目录残留。

结论：仅卸载/重启/覆盖并不能解决根因。

### 阶段 2：补 Dashboard 资源与启动诊断

加入：
- Dashboard resource path 输出；
- `WEB_VERSION.txt`；
- 本地资源服务；
- 前端资源诊断。

作用：可以明确看到程序实际从 `_internal/web` 加载资源，排查范围明显缩小。

### 阶段 3：#57 构建失败

日志出现：

- `Successful compile`
- 随后报 `Installer exe was not generated`

实际根因：

`build_installer.ps1` 的检测逻辑在错误位置找 Setup，甚至曾排除正确的 `installer_output`。

### 阶段 4：修复安装器检测与构建清理

处理：

- 修复 `build_installer.ps1`；
- Workflow 构建前删除 `build/`；
- 删除 `dist/`；
- 删除 `installer_output/`；
- Inno Setup 安装时删除旧 `{app}\_internal\web`。

结果：构建链稳定，避免旧构建污染新包。

### 阶段 5：Enterprise R2 资源隔离

处理：

- 新建固定 Enterprise Dashboard 来源；
- 引入 Build Marker；
- Workflow 在源码阶段验证 Marker；
- PyInstaller 完成后再次验证 `dist/.../_internal/web` Marker。

意义：证明“新前端确实进了 EXE”，不再只凭页面猜测。

### 阶段 6：发现旧端口 / 旧进程干扰

即使新包内部前端正确，旧版 `127.0.0.1:8765` 仍可能继续运行并提供旧页面。

这解释了为什么：

- 新安装包内部已经是新资源；
- 但浏览器仍然能看到旧 Dashboard。

### 阶段 7：Enterprise R3 完全隔离

R3 采用：

- 独立 AppId；
- 独立安装目录；
- 独立桌面快捷方式；
- 独立本地端口 `8876`；
- 独立 Build Marker；
- 保持 PyInstaller 前后双重前端校验。

GitHub Actions `Run #65` 成功。

## 3. 问题点、根因与永久解决方案

### 3.1 新包仍显示旧 9 卡片 Dashboard

**现象**：安装新包后页面不变，浏览器仍显示旧界面。

**根因组合**：
- PyInstaller 前端资源来源曾不明确；
- 旧 `_internal/web` 残留；
- 构建目录可能复用旧产物；
- 旧本地服务仍占用 `8765`；
- 新旧版本没有完全隔离。

**永久修复**：
- R3 固定 Enterprise 前端来源；
- 打包前后双重 Marker 校验；
- 构建前清理 `build/dist/installer_output`；
- Inno Setup 安装前清理旧 `_internal/web`；
- R3 使用独立 AppId、安装目录和 `8876` 端口。

**状态**：已验证解决。

### 3.2 Installer 已生成但脚本误判失败

**现象**：Inno Setup 显示 Successful compile，随后 Workflow 报 Installer 未生成。

**根因**：`build_installer.ps1` 检测路径错误。

**修复**：直接检查 `installer_output` 中的 Setup EXE。

**状态**：已修复。

### 3.3 旧构建文件污染新包

**修复**：Workflow 构建前强制删除：

- `build/`
- `dist/`
- `installer_output/`

**状态**：已修复。

### 3.4 无法判断到底打包的是哪套前端

**修复**：

- `WEB_VERSION.txt`
- HTML Build Marker
- 源前端 Marker 校验
- PyInstaller 产物 `_internal/web` Marker 二次校验

**状态**：已建立长期发布闸门。

### 3.5 旧进程抢占同一端口

**根因**：旧版和新版共用 `8765` 时，浏览器无法仅凭安装包区分当前服务来源。

**修复**：R3 固定 `8876`。

**状态**：已验证。
