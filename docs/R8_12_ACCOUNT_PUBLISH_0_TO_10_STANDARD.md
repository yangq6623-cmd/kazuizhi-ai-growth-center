# R8-12 统一账号资产与真实发布：0→10 执行标准

## 目标

这个板块不是“绑定账号页面”，而是卡嘴子所有外部平台执行的基础设施。它必须保证：

- 账号身份长期稳定，不随 Mission、服务、区域、手机或软件升级改变。
- 授权可以过期、刷新或重新扫码，但不会创建一个“新账号”。
- 手机是执行设备，不是账号身份本身。
- Mission 只引用稳定 `account_id`，由路由器决定 API / 真机 / 人工闸门。
- 只有真实平台 `Post ID/Content ID + URL + Receipt` 才能记为已发布。
- 覆盖升级、断电、网络失败、设备更换、授权过期都不能让已有更完整状态倒退为空。

## 统一对象模型

### Account Asset

长期业务资产。主键：`ACC-<PLATFORM>-<ID>`。

包含：平台、显示名、平台主体标识（如已取得）、授权元数据、服务范围、区域范围、首选设备、历史旧账号映射。

不包含：access_token、refresh_token、client_secret、密码。

### Authorization

可替换凭据，不等于账号身份。

状态只允许：

- `connected`
- `needs_authorization`
- `platform_limited`
- `disabled`

授权过期只触发“重新授权”，绝不新建 Account Asset。

### Device Asset

长期设备资产。主键：`DEV-...`。

保存设备型号、真实 ADB 设备 ID、在线状态、健康、最近在线时间。设备可替换，不改变账号历史。

### Mission Route

Mission 不保存临时绑定关系，只保存需要的平台/区域/服务/能力。路由器按实时状态选择：

1. 官方 API 可用且已获发布 scope → `official_api`
2. 否则真实设备在线且账号真实验证 → `real_device`
3. 授权过期 → `reauthorize`
4. 设备离线 → `wait_device`
5. 平台能力未批准 → `platform_limited`
6. 没有账号 → `add_account`

### Publication Plan

由老板已确认的成片产生。必须保存：video_id、growth_id、stable account_id、route_kind、device_id（如果使用真机）、平台、文案、排期、状态。

计划不是发布结果。

### Receipt

真实发布唯一成功证据。成功必须同时有：

- 真实平台内容 ID / Post ID
- `http/https` 真实 URL
- 执行时间
- 对应 plan_id / account_id

没有以上证据只能停留在待验证/失败/需人工，不得显示“已发布”。

## 0→10 成熟度

### 0 分：页面演示

有表单、有按钮，但没有稳定身份、恢复、真实执行与回执。

### 1 分：临时绑定

账号与服务/区域/设备/Mission 混在一个表单中。重启或换任务可能需要重新绑定。

### 2 分：稳定账号 ID

账号拥有永久 `account_id`，Mission 不再创建账号。

验收：同一账号切换服务、Mission、设备后 `account_id` 不变。

### 3 分：账号 / 授权 / 设备解耦

授权过期只重新授权；设备离线只提示设备离线；换手机不改变账号。

### 4 分：自动路由

Mission 自动选择账号和执行设备，不要求老板手动匹配服务主线。

### 5 分：恢复可靠

覆盖升级、异常退出、断电、空状态写入不能覆盖更完整的最后可信状态；支持部分恢复，不要求本地完全为空。

### 6 分：官方授权能力

支持平台官方 OAuth / 扫码 / 回调适配器。没有官方应用凭据时必须明确显示“未配置”，不得模拟成功。

### 7 分：双执行通道

官方 API 优先，真机兜底。任何验证码、人脸、风控、账号异常自动转人工。

### 8 分：真实发布闭环

老板审核 → 路由 → 发布计划 → 真机/API 执行 → 真实 Receipt → Mission Ledger 回流完整贯通。

### 9 分：多账号多平台调度

同平台多账号、多设备、限额、冷却、失败切换、平台健康、内容去重都由调度器自动处理。

### 10 分：商业级自治

平台授权、设备池、发布、回执、效果、咨询订单归因形成持续闭环；老板只处理授权、风控、最终高风险闸门。

## 当前 R8-12 必须达到的最低发布门槛：7.5 分

在正式继续多平台推广前，本板块必须全部通过以下验收：

1. `卡嘴子本地服务维修` 只存在一个稳定 Account Asset。
2. ELE-AL00 作为 Device Asset 独立存在。
3. 服务从“水电”切换到“家电”不要求重新绑定账号。
4. Mission ID 改变不影响账号身份。
5. 换手机不改变 account_id。
6. 软件覆盖升级后账号、设备、已审核视频、发布计划不丢。
7. 空状态或低信息状态不能覆盖更完整快照。
8. 授权过期只出现“需授权”，扫码后恢复同一个 account_id。
9. 设备离线只出现“设备离线”，不会把账号判成未登录。
10. 同一视频重复调度不会创建重复 plan / dry-run。
11. 官方 API 未配置时显示真实限制，不伪造 API 能力。
12. 真机 dry-run 必须停在最终发布动作前。
13. 成功发布必须带 Post ID/Content ID + URL。
14. 老板主界面不再出现“服务主线 + 保存账号并绑定真机”这种临时身份模型。
15. CI 必须覆盖“真实启动入口已挂载 R8-12”，不能只测试孤立模块。

## 故障注入测试矩阵

每个 Candidate 必测：

- 覆盖升级
- 程序强制结束后重启
- Windows 重启
- 手机 USB 拔出/重新插入
- ADB offline → online
- 抖音退出登录
- OAuth/token 过期
- 换手机
- Mission 切换
- 服务切换
- 区域切换
- 已审核视频存在时重复 autostart
- 网络断开
- 平台验证码/人脸/风控
- 发布执行失败
- 回执缺 URL
- 回执缺 Content ID
- 数据文件部分为空/损坏

## 老板界面标准

老板日常只看四类状态：

- 已连接
- 需授权
- 设备离线
- 平台限制

技术细节进入“查看详情/审计”，不在主流程要求老板理解 token、probe、scope、device binding、Mission mismatch。

## 不可违反的真值规则

1. 账号登录 ≠ 发布成功。
2. 老板审核 ≠ 发布成功。
3. 发布计划 ≠ 发布成功。
4. 真机 dry-run ≠ 发布成功。
5. 只有真实 Receipt 才是发布成功。
6. 任何恢复都只能恢复已存在证据，不能补造外部结果。
7. 任何新状态不得静默覆盖更完整的最后可信状态。
