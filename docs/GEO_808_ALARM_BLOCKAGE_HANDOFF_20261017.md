# 卡嘴子 #805 / GEO 2.2.2.808：自动调度与阻塞分类交接

## 背景
#804 + Chrome 2.2.2.807 已安装，真实截图显示1分钟心跳更新，但「最后运行：尚未执行」。
源码发现 `ensureAlarm()` 在每次 MV3 后台工作进程唤醒时执行，`chrome.alarms.create` 会重设同名闹钟，导致3分钟执行周期不断推迟。
另 `geo_browser_agent.block` 将 `execution_error` 等技术失败错归类为平台授权失效，历史待授权计数达99，但其具体成因尚未逐项核验。

## 本次目标
- 3分钟调度在1分钟心跳/Chrome MV3后台重启时不重置，仍能自动走注册、心跳、领取、回执链路。
- 技术采集错误只使该任务转为失败，不伪造登录故障，不整个平台熔断。
- 真正的验证码、账号权限或登录问题仍进入授权阻塞，不绕过第三方风控。
- 只读区分历史授权阻塞中的技术原因、真实授权和未知原因，不批量重试99项。
- 所有旧50问、真实Receipt、历史轨迹完整保留，不把失败算成功。

## 修改文件
- `05_V2.0.0_Source/browser_extension/kazuizhi_geo/service-worker.js`：检查原闹钟存在且周期匹配再创建，免得1分钟心跳推迟3分钟业务循环。
- `05_V2.0.0_Source/integrations/geo_browser_agent.py`：`execution_error` 等技术失败与授权错误分流；迟到的失败回调不能覆盖成功Receipt；心跳不抹去最近错误。
- `05_V2.0.0_Source/core/geo_validation.py`：只读 `blockage_diagnostics` 分组及 `reason_class`，不修改旧队列。
- Chrome `2.2.2.808`：完整保留 #804 真实发送确认/分段采集和独立心跳逻辑。
- 新增 `test_geo_alarm_no_reset.js`、`test_geo_blockage_truth_805.py` 和 `test_geo_extension_808.js`。

## 约束
- `SUBMITTED` 不是 `INDEXED`，正常 `ready` 和50/50历史记录不代表当轮真实GEO曝光；只使用真实外部独立Receipt验收。
- 未确认发送、采集超时以及不明网络故障不批量自动重试，防止重复发问与虚假证据。
- 禁止自动处理验证码或绕过平台登录风控。
- 历史99条阻塞不能假定全部都是技术问题；需读新诊断分类后决定安全恢复范围。

## 验收流程（真实电脑）
1. 备份 #804；安装构建成功的 #805 Windows程序及 Chrome 2.2.2.808，关闭全部旧扩展，并刷新已打开的AI平台页面。
2. 等待3分钟；观察扩展「最后运行」变为新时间，不需要人工点击按钮，确认心跳1分钟更新且不会重置业务定时器。
3. 浏览器代理状态仍显示已连接，检查新队列的 `blockage_diagnostics`。
4. 核对 `/api/r8-19/geo/queue` ：技术历史失败、真实授权与未知原因各自数量；要求总数与历史99条对齐，不自动归零。
5. 当真实任务队列为0时不得伪造新任务或Receipt；通过业务授权并完成风险检查后方可依策略创建一个可执行的新问题任务。
6. 确认实际豆包问题发送成功，页面返回与当前提问相对应的新回答，保存了唯一回执；没有真实回答就没有正式Evidence。
7. 测试已成功Receipt的迟到失败回调不得降级，验证码等真正授权阻塞不得反复自动重试。

## 回滚
出现问题，关闭 2.2.2.808，重新启用 2.2.2.807，并从备份恢复 #804；严禁清空Evidence、队列或连接密钥。Windows安装包仍可能沿用历史 EXE 内部命名，应以正式GitHub构建编号为准。
