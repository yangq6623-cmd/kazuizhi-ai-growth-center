# #812 GEO 自动领取→执行→回执闭环修复说明与交付门禁

## 背景
#811 Windows 构建和 Evidence 接口测试通过，现场 Chrome 扩展 `connected=true`、心跳51秒、国内五平台 ready。旧队列807条中，10条 `cloud_auto/api` 不属浏览器，73条历史技术超时结果不确定，正式矩阵50/50已完成。因此浏览器领取时 `queue_empty` 并非扩展掉线；工作台2.5秒 status 请求失败却显示“已离线”，造成误判。现有两段式回执写入存在崩溃窗口；旧豆包试跑选题范围过宽。

## 目标
不伪造新曝光、不重发历史不确定任务的前提下：合法合格任务可自动领取，匹配唯一平台，真实外部网页原始回答可自动回传，并精确一次保存 Evidence/Receipt。用户可区分“代理在线但无任务”“代理状态暂不可核实”和真正离线。

## 模块结构
- `core/geo_validation.py`：任务领取序列化；Evidence 以 task_id 为幂等键；回执已写但队列未完成的崩溃后自恢复；一次/24h的安全正式复测（仅完成50/50后、真实A级/B级成功题目、没有历史未决尝试的相同平台题位）；豆包一次性 canary 限定自己10题；复测失败不自动重发
- `integrations/geo_browser_agent.py`：鉴别真实代理和执行器 ID；无任务时按上述规则安全生成并领取正式复测任务；迟到失败不可覆盖成功；返回最近复测派发原因
- `backend/r8_19_geo_validation_patch.py`：Receipt 成功落盘后立即发送响应，后续分析刷新在守护线程执行，不在 Chrome 15 秒 HTTP 超时内同步等待
- `web/geo-growth-os.js`：代理状态请求超时为“未知”而不是假报离线，显示 `last_retest_reason`
- 原 Chrome 扩展：保留现有已验收的 2.2.2.808 领取/执行、同平台和不重复提交保护，无需重新部署脚本

## 安全与限制
- 不会将 `cloud_auto/api` 的10条旧任务交给 Chrome；不重发73条历史技术超时或一切 `failed/authorization_required` 不确定回答
- 安全复测从真实 A/B 成功题目的既有固定50问选取，仅在超过24小时、同题位无未决旧执行时建立；全系统每滚动24小时不超过1条；不得生成模拟 Evidence
- 不跨平台选题；一个任务只产生一条 Receipt；回执落盘中断后按同任务+run_id+问题标识恢复旧证据，绝不制造第二条
- CAPTCHA/风控、凭证和网页授权仍按现有规则暂停，不尝试绕过
- 保留 #811 原有 GEO 历史数据和安装包，不直接覆盖 main

## 验收与执行步骤
1. Python 隔离目录生成合成50/50数据及两个不同阻塞的旧任务；以五平台已登录的代理模拟自动领取，确保只创建一个安全复测，历史任务内容/状态不变
2. 5线程争抢时不得领取第二条、不多发复测
3. 同一合法回执提交2次，Evidence ID相同、账本只新增一行
4. 模拟回执写入成功、队列状态更新中断；再次提交应恢复原 Receipt 且状态变succeeded
5. 已成功的任务收到迟到超时告警不得降为失败
6. 本机 HTTP真实POST模拟慢分析，Receipt 响应不得等待4秒分析任务，证据真实保存
7. 复跑 #808安全领取、#809轻量响应与 #811 GEO 证据/并发完整回归、Windows打包、启动、升级、卸载测试
8. CI全部通过且本机 Chrome 现场测试无误才交付新版；Windows CI成功不能单独证明外部AI已真实执行或24h稳定

## 输出与回滚
交付独立PR、提交SHA、Windows构建、逐项结果、回滚到#811的说明。不得宣传自动推荐/AI引用增长，除非提供实际外部链接、原始回答与新的正式回执。
