# 卡嘴子 R8 社媒终端运行规则（多平台串行 + 内容相关节奏）

日期：2026-09-18  
项目：卡嘴子 AI 自动化运行推广项目  
分支：`codex/v2-r8-growth-ops`

## 1. 终端模型

R8 社媒执行层采用“以真实手机为执行终端、以平台账号为执行通道”的模型：

- 一台真实 Android 手机 = 一个社媒运营终端；
- 一台手机可以安装并绑定多个社媒平台；
- 同一台手机上的平台任务按队列串行执行；
- 多台手机之间允许并行运行；
- 设备唯一身份以真实设备 ID 为准，手机号只作为可选属性，不作为设备主键；
- 每个平台账号独立记录登录状态、授权状态、风险状态、任务状态和运行结果。

示例：

`手机01 → 抖音 → 小红书 → 快手 → 视频号 → 微博 → B站`

`手机02 → 抖音 → 小红书 → 快手 → 视频号 → 微博 → B站`

手机01与手机02可以并行，但单台手机同一时刻只执行一个前台平台任务。

## 2. 平台切换规则

每个平台任务结束后，R8 必须先完成：

1. 当前平台结果保存；
2. 任务回执与日志写入；
3. 风险状态检查；
4. 必要的短暂空闲/切换阶段；
5. 再打开下一平台。

不得在同一台手机上同时操作两个前台 App。

## 3. 浏览与观看节奏必须内容相关，禁止机械固定时长

已确认：R8 不能采用“所有内容固定观看 X 秒、固定间隔滑动、固定路径重复”的机械执行方式。

浏览/观看决策应根据当前内容本身和任务目标动态变化，例如：

- 与本地维修、用户痛点、平台趋势或当前研究主题明显无关的内容，可以较快跳过；
- 与任务主题相关但信息价值一般的内容，可读取部分内容后继续；
- 高相关、高信息价值内容，可观看更久，必要时完整阅读/观看，并提取公开信息；
- 需要读取评论、标题、正文或公开互动数据时，停留时间由实际读取任务决定；
- 视频/图文长度、信息密度、当前任务目标不同，处理时间也应不同；
- 不把“固定秒数”作为所有内容的统一模板。

核心原则：**节奏变化来自内容相关度、信息价值和当前任务，而不是为了伪装自动化、规避平台检测或绕过平台风控。**

## 4. 明确禁止的“模拟真人”做法

R8 不得为了逃避平台识别而实现以下能力：

- 专门伪造“真人随机轨迹”以规避自动化检测；
- 伪造设备指纹、IMEI、Android ID、GPS、IP 或网络身份；
- 隐藏自动化框架、绕过平台风险验证；
- 绕过验证码、短信验证、人脸验证；
- 人为制造虚假互动、虚假评论、虚假订单、虚假评价；
- 为了“像真人”而进行无任务价值的刷量、互刷或批量骚扰。

如平台规则不允许某类自动化行为，R8 必须停止该类执行或切换为官方 API / 人工操作。

## 5. 合规的“自然使用节奏”定义

R8 中“更像真实使用”的目标，正式定义为：

> **不是欺骗平台，而是避免机械化固定模板，让系统依据内容、任务、平台状态和实际读取需要做不同处理。**

允许的动态因素包括：

- 内容相关度；
- 内容长度；
- 视频是否已获取足够信息；
- 是否需要读取评论；
- 是否需要记录公开信号；
- 当前平台任务优先级；
- 当前账号健康状态；
- 当日任务剩余量；
- 平台正常操作规则与频率限制。

## 6. R8 运行时应记录“为什么停留/为什么跳过”

为了后续审计和优化，平台学习任务应记录动作原因，而不仅是动作本身。

例如：

- `skip_reason = low_relevance`
- `watch_reason = high_relevance`
- `read_comments_reason = user_pain_point_signal`
- `full_watch_reason = content_gene_candidate`

后续 R8-02 平台学习必须基于这些真实原因分析“什么内容值得继续研究”，不能只记录观看秒数。

## 7. 与自动唤醒/防熄屏联动

在一个平台任务周期内：

- 普通熄屏可自动唤醒；
- 任务执行期间保持必要的亮屏状态；
- 平台切换期间继续保持设备可执行；
- 遇到密码锁、人脸、短信、验证码、异常登录或平台风险提示时立即停止并转人工；
- 人工处理后必须由明确的“交还 R8”动作恢复执行；
- 不允许自动绕过安全锁。

## 8. 后续实现要求

R8-02 进入单平台学习时，必须把以下能力纳入验收：

- 非固定观看/阅读时长；
- 内容相关度驱动的跳过/继续/完整读取；
- 可解释的动作原因；
- 平台切换后任务状态连续；
- 单手机串行、多手机并行；
- 账号/设备风险熔断互不影响其他正常手机；
- 所有动作可审计；
- 不实现为规避平台检测服务的“反风控真人模拟”。

本文件为 R8 社媒终端与平台学习阶段的正式设计约束，后续实现、测试和交接必须保持一致。
