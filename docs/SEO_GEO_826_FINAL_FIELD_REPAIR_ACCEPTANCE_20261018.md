## 2. 根因

`prepare_phase3_assets()` 只把“待重新发布”或本地阶段视为已准备；当同一 action 已成功发布、`republish_pending` 被清除后，下一轮会再次把完全相同的 revision 标成待发布。与此同时，Opportunity 同步逻辑选择同一 action 的最后一条发布事件，造成每次重复核验都把复测时间向后推。

## 3. 修复

1. 同一 action 已存在含 `deploy_receipt`、公网 URL 的验证事件后，不再重复生成或重新发布。
2. 同一 revision 有多条发布核验记录时，以第一条有效公网 Receipt 作为曝光与复测基准；后续重复 Receipt 保留在审计账本，但不延期复测。
3. 没有 Task、Signal、Receipt 的窗口按有效公网时间双向校正；已有 Task/Signal/Receipt 的窗口保持不变。
4. GEO 列表新增“有效公网时间”和“发布回执”显示，避免把普通更新时间或重复部署误认作新曝光。
