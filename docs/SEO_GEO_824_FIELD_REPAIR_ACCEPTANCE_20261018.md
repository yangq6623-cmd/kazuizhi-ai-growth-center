## 6. GEO 偶发空白与 5 秒超时

- 当前 Chrome 对机会表连续 11 次只读采样稳定：每次 13 行，12 个 `SUBMITTED`、1 个 `PUBLISHED`、2 个 24h 完成；未复现空白。
- #817 Windows 原始 GET 计时：liveness 109ms、fast-health 21ms、http-health 16ms、fast-ui 20ms，均 HTTP 200。
- #824 源码的 owner fast-ui 超时预算已经是 8 秒，不是 5 秒；`fast-ui` 只读内存缓存，磁盘账本刷新在后台线程完成。
- 因此没有证据证明 `fast-ui` 的响应体计算本身需要 5 秒。历史 5 秒现象更符合本地 HTTP handler 被并发懒加载/旧账本读取占用后，前端 AbortController 先超时；但缺少故障发生当时的 `/http-health` 快照，不能把这一点写成已完全证实的单一根因。
- 本轮保留缓存快照、健康回退和串行轮询；新增 13 条机会的发布时间与到期时间展示，空白时继续显示“明细待同步”，不会显示成 0。
