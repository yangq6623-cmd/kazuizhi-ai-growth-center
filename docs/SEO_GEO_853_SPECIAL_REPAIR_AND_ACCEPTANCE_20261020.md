# 卡嘴子 #853 GEO 专项修复与验收说明

日期：2026-10-20
基线：Commit `e041ffdb186f4d75605a0e009822ea2f9120ce0a`（现场安装 #853）

## 背景与目标

本次仅处理 GEO 真实外部 AI 执行链的四个已证实问题：空队列后的安全复测调度、跨平台冷却互相阻塞、豆包发送按钮异步启用导致的误判，以及 `fast-ui` 在前端请求队列中的 8 秒超时。保留既有 R7/R8、Mission、50/50 Evidence、历史 Task/Receipt 及 78 条待核查记录。

## 现场只读证据

- GEO 调度持续更新，国内五平台会话均处于 ready，浏览器代理在线。
- 正式矩阵为 50/50；最近真实外部回执停留在 2026-10-19 00:42（北京时间）。
- 最近领取结果为 `queue_empty`；自动复测返回 `global_retest_cooldown`。
- 历史待核查 78 条，其中技术超时 73 条；本次未重试、未改写。
- `fast-ui` 请求 8 秒超时后退回缓存，但 Evidence 缓存本身健康，说明故障点在浏览器端共享请求预算，而非证据账本读取。
- 豆包失败为 `send_button_not_enabled`；原实现填入文本后立即检查按钮，未等待 React 完成启用。

## 根因与最小修改

1. `web/build_info.js`：将只读 `fast-ui` 加入与健康/Evidence接口相同的预算旁路，避免被两个慢请求长期占槽。
2. `core/geo_validation.py`：把“任一平台复测后全局 24 小时阻塞”改为“同平台 24 小时冷却”；同问题的回执年龄门槛、失败/不确定任务隔离及零重试规则保持不变。返回阻塞 Task、创建时间、剩余秒数和下一次允许时间。
3. `integrations/geo_browser_agent.py` 与 `web/geo-growth-os.js`：保存并显示冷却原因、阻塞 Task 和下一次允许时间，区分无任务、冷却和技术故障。
4. Chrome 扩展 `content-agent.js`：豆包仅等待最多 4 秒，让明确命名且紧邻输入框的发送按钮变为可用；仍禁止点击任意图标、模拟 Enter 或不确定结果重发。扩展版本为 `2.2.2.854`。

## 安全限制

- 未创建新 Mission，未清理或迁移账本，未改变已完成 Evidence。
- 未取消平台级冷却；同平台仍严格限制每 24 小时最多一个自动复测。
- 未发送真实外部问题，未补造 Receipt/Evidence，未重试历史超时或发送状态不确定任务。
- 生产环境写入、订单、资金、账号授权不在本次范围。

## 测试与验收

隔离测试覆盖：请求预算饱和时 `fast-ui` 直达、跨平台冷却隔离、同平台精确阻塞信息、并发领取唯一性、Receipt 幂等、崩溃恢复、晚到失败回调隔离、豆包按钮延迟启用、无明确按钮时拒绝发送、扩展版本兼容及 R7/R8 既有 GEO 回归。

Windows CI 需完成源码门禁、安装包构建、Defender、静默安装、覆盖升级、数据保留和卸载测试后，候选才可交付。

本地源码门禁均通过。两项依赖 Selenium 新建本地 Chrome 会话的旧浏览器用例在当前 Linux 容器中无法启动 Chrome，未进入断言阶段；它们必须以 Windows CI 结果为准，不能记作本地通过。

## 尚未通过的现场门槛

- 必须在出现合格且从未发送、或按规则到期的复测 Task 后，由新扩展完成真实领取、外部回答和 Evidence 保存，才能判定端到端通过。
- 连续 24 小时自然运行尚未实际经过，不得宣称 24 小时无人值守验收通过。
