## 3. 本轮主要问题与最终解决方案

### 3.1 旧 Dashboard 一直被加载

现象：
安装新包后仍显示“卡嘴智 AI 自动化运营中心 V1.9.5”旧 9 卡片页面。

根因曾包含：
- PyInstaller 前端资源来源不明确；
- 旧 `web` 目录残留；
- 构建流程曾可能复用旧输出；
- 安装器与最终 Artifact 检测路径不一致；
- 旧本地服务端口/旧进程可能继续提供旧页面。

最终处理：
- Enterprise 前端资源改为固定来源；
- PyInstaller spec 明确只打包 Enterprise Dashboard；
- Workflow 在打包前后都做前端资源校验；
- 每次构建前清理 `build/`、`dist/`、`installer_output/`；
- Inno Setup 安装时清理旧 `_internal/web`；
- R3 使用独立安装身份与独立安装目录；
- R3 运行端口改为 `8876`，与旧版 `8765` 隔离。

### 3.2 Installer 已生成但脚本误判失败

现象：
日志出现 `Successful compile`，但随后报 `Installer exe was not generated`。

解决：
`04_Build/installer/build_installer.ps1` 改为直接检查 `installer_output` 中的 Setup EXE，不再从错误路径递归查找并排除正确输出目录。

### 3.3 旧构建文件污染新包

解决：
Workflow 构建前强制删除：
- `build/`
- `dist/`
- `installer_output/`

避免旧 EXE、旧 web、旧 Setup 被重新打入新包。

### 每次升级必须做
1. 修改代码前先确认当前 main 可构建；
2. 前端版本必须带唯一 Build Marker；
3. Workflow 打包前检查源前端 Marker；
4. PyInstaller 后再次检查 `_internal/web` Marker；
5. 只有两次校验都通过，才允许生成 Installer Artifact；
6. 新安装包必须实际安装测试；
7. 安装测试必须确认浏览器打开的是新端口/新 Build，而不是旧进程；
8. 成功版本必须更新本文档、CHANGELOG、VERSION 和 BUILD_STATUS。
