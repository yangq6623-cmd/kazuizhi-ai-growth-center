# V2.0.0 Beta R7 Core 可信运营底座交接

本版完成用户交接规划的第一大板块，建立可追踪的本机任务工作流。R6 的复盘、内容、经营分析、Memory 和连接管理继续保留；R3 稳定版源文件及既有交接资料保持原样。

## 本版可以做什么

- 在“任务与员工”创建人工运营任务、本地每日复盘或本地系统体检任务。新任务先进入待审批。
- 本机操作员批准后，人工任务仍需人工点击开始并填写真实完成结果；本地复盘和体检任务由 15 秒检查一次的本机调度器在到期后执行。
- 进度显示已完成步骤数。当前每项任务只有一个可验证步骤，因此只会显示 0% 或完成后的 100%，不会模拟中间进度。
- 每次状态变化进入带哈希链的审计记录。中断时正在执行的本地任务标记失败，需人工检查后重试，不会悄悄重复执行。
- 八类 AI 员工在界面登记职责。登记不代表八个模型或后台进程已经运行。
- 模型路线默认使用本地规则引擎；只有外部模型通过真实连接测试才会加入可用路线。ChatGPT 网页会话不是本机程序的自动连接。
- 第一次启动 R7 时，复制 R6 的任务、日历、Memory 和连接配置到数据目录内的 `r7/backup_r6`，并保留迁移记录。不会修改原 R6 数据文件。

## 权限及安全边界

当前是只监听 `127.0.0.1` 的单用户桌面程序，尚未建立多用户身份系统。审计中的 `local_operator` 只表示本机操作，不证明某个具体人的身份。浏览器跨来源写入请求会被拒绝。可执行任务类型采用白名单；自动发布、支付、退款、提现、改价、结算等没有执行器，不会作为任务运行。内容和计划继续是待审核草稿。

## 验收流程

1. 创建一个人工任务，检查其状态为“待审批”、进度为 0%；批准、开始、填写真实结果后才显示 100%。
2. 创建并批准本地体检，检查调度器完成后有结果与审计事件。
3. 尝试未授权任务类型和跨来源写入，确认接口拒绝。
4. 检查未配置外部模型时只显示本地路线；测试连接通过后才显示外部路线。
5. 检查 R6 数据备份、重启恢复、审计完整性及 R3 哈希保护；完成 Windows 安装、覆盖安装、卸载和用户数据保留验证。

## 第二大板块仍待实施

真实经营数据源、产品及区域档案、推广渠道授权、审批后发布和真实转化归因不在 R7 Core 范围。这些能力需要明确的数据来源、权限和字段口径后才能接入；未接入时继续显示“未接入”。
