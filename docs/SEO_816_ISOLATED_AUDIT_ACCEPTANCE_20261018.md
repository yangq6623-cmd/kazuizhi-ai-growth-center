# #816 SEO 独立巡检与人性化验收说明文档

## 背景
#815 已证明 GEO 基础调度稳定；SEO 原始站点诊断停留在 2026-10-15，历史阻塞七项与持续运行分离。不得动 GEO 50 问、领取、浏览器版本和正式 Evidence。

## 目标
1. 24 小时内已有新鲜诊断则不重复扫描；没有则由 SEO 自治工作循环在后台异步启动；失败三小时后重试，不阻塞五分钟调度。
2. 站点网络故障保留异常原因；不可抓取不当作缺少标签，避免误报。
3. 在 SEO 技术检查区明确列出扫描时间、新鲜度、七项原始问题和自动巡检错误。
4. 保持 /seo/ 与主站首页的权限边界；只通过真实公网部署回执计数。

## 结构与步骤
- promotion/search_growth.py：自动巡检状态、网络错误隔离、24 小时新鲜度和后台单任务约束。
- core/seo_geo_autonomy.py：仅 SEO 自治调用，非阻塞排程。
- web/r8_13_seo_geo.html：展示全部原始阻塞和检查时间，已有手动官网检查功能保持可用。
- 04_Build/v2/test_seo_816_*：模拟离线、七项旧问题、去重调度、UI 和 GEO 扩展保护。
- GitHub CI：先跑 #816 独立测试，再运行继承的 GEO #811–#815 和 Windows 完整构建。

## 限制
- 不会直接修改公网首页或服务器 Web.config；七项历史问题不会因升级客户端就直接标记修复。
- 不重新发任何外部 AI 问题；不放开 GEO 冷却或历史 73 条失败任务。
- 无人工网站授权、缺少平台索引数据时保持待确认；提交不计收录。

## 验收与输出
- 独立 4 类测试全通过；Windows CI 编译、安装、覆盖升级、回滚和 GEO 回归无故障后方可交付。
- 安装 #816 后开始 8 小时连续运行观察：保留调度时间、巡检记录、官网状态、发布与提交 Receipt 和异常；次日逐项复核真实公网/搜索平台和获客信号。
- 若未得到真实平台回执，不能宣称 SEO 成效闭环 100%。
