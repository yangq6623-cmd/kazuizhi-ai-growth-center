# 第一阶段：系统稳定、外部通道与 GEO 证据验收

日期：2026-10-10（Asia/Shanghai）

## 本阶段交付

1. Windows 登录后由用户级计划任务启动监督器；应用异常退出后自动重启，端口已有健康实例时不重复启动。
2. 保留当前 Windows 用户的 DPAPI 凭据边界，不把用户授权迁移到 LocalSystem，也不把用户级守护误称为系统服务。
3. 建立连续 7 天验收账本，每 60 秒记录进程、工作线程、连接器和 GEO Evidence 状态，并统计中断、重启、成功率及静默间隔。
4. Google Search Console 支持 refresh_token 自动续签；401 时自动续签并重试一次。百度、IndexNow、Google 均显示最近一次真实成功或失败。
5. 360 搜索明确为站点验证、Sitemap 与监测通道；没有可审计官方程序化回执时不标记 SUBMITTED。
6. 豆包复用现有已验证 API 做 GEO/AI 可见性监测，普通回答只计 C 级运营 Signal；抖音只有取得真实发布 scope 后才显示发布就绪。
7. GEO 界面分别显示提及、推荐、引用、证据完整性、人工/自动正式验证和 24h/72h/7 天复测覆盖。
8. 可一次建立剩余正式 50 问队列；每题只有保存真实外部问题、完整原始回答、模型、时间和外部会话/截图/回执后才计入 A/B。

## 7 天验收通过条件

- 持续时间达到 7 天；
- 运行可用率不低于 99.5%；
- 工作线程成功率不低于 95%；
- 最大无采样间隔不超过 15 分钟；
- 固定 50 问正式 A/B 达到 50/50；
- 正式证据不存在字段缺失。

状态只允许为：`in_progress`、`passed`、`needs_review`。安装和启动候选包只能开始验收，不能立刻宣称 7 天验收通过。

## 真实边界

- 当前现场正式 GEO 仍为 2/50；代码回归、豆包普通 API 回答、本地模型回答都不能增加该数字。
- 访问、咨询、订单和收入的完整归因链属于第二阶段；第一阶段界面明确显示尚未接通，不生成假数据。
- 抖音自动发布需要开放平台真实账号、应用审批和发布 scope；缺少权限时保持“待授权”。
- 360 搜索没有取得官方可审计提交接口时保持监测/人工站点配置状态。

## 可核验接口

- `/api/r8-24/geo-growth/liveness`：不读业务账本的本机存活探针。
- `/api/r8-24/geo-growth/evidence-compact`：锁外原子快照，避免 Evidence 阻塞主界面。
- `/api/r8-25/phase1-acceptance`：7 天验收进度、阈值、检查项和监督器状态。
- `/api/r8-16/search-submit/status`：搜索/监测连接器配置、授权、最近真实成功/失败。

## 发布门禁

只有源码回归、真实 Chrome、打包验证、静默安装、覆盖升级、卸载数据保留和 GitHub Actions Windows 构建全部通过后，才可交付候选安装包。连续 7 天实机验收在安装候选包后开始单独计时。
