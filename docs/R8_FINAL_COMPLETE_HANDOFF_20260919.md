## 账号矩阵

- 一台真机可绑定多个平台，也可绑定同一平台的多个账号别名。
- 账号包含主品牌号/服务矩阵号、地区、服务类型、L1-L4 自动化等级。
- 同一台手机前台任务串行执行；第一台试点验收通过前不开放第二台并行。
- 同一需求只选择一个账号触达；用户拒绝后停止联系，矩阵号不得重复触达。

## 不伪造原则

- 未接平台 Connector 时，只能人工导入真实公开信号或真实回执。
- 未检测到 NVIDIA GPU/模型时，视频任务停在“等待 Worker”。
- 发布成功必须保存平台内容 ID、真实 URL、执行时间和执行来源。
- 订单归因只接受已验证只读经营数据或人工确认，不执行支付、退款、提现、结算、改价等资金动作。

## 数据与升级

R8 数据继续保存在用户目录下的既有 V2 数据根中，覆盖安装和卸载不会删除用户业务数据。新增命名空间为 `r8/control.json` 和 `r8/growth_ops.json`，旧账号记录会自动补齐角色、地区、服务类型和自动化等级字段。

## 安装包安全修复

Preview #236 的无签名单文件安装器触发了本机 Microsoft Defender 的 `Trojan:Win32/Wacatac.B!ml` 机器学习检测。Final 安装器取消自定义 `taskkill /F /T` 代码，改用安装器标准应用关闭机制，并从 LZMA2 固实压缩改为 ZIP 非固实压缩。CI 和最终下载文件都执行 Defender 自定义扫描与 SHA-256 校验。

## 验收顺序

1. 安装并启动，确认左下角显示 `V2.1.0 R8 Final / R8-08`。
2. 连接真实 Android 手机，确认设备、截图、触控和人工接管。
3. 在社媒中心绑定账号并人工完成登录授权。
4. 在“R8 增长总控”录入一条真实公开需求，走完增长 ID、内容审核和发布队列。
5. 真实发布后回填平台内容 ID 与 URL，再录入消息、线索、订单和 24h/72h/7天指标。
6. 运行 R8 上线体检；没有现场条件的项应显示“待配置/待验收”，不应显示虚假通过。
