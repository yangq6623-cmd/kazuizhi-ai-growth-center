# 卡嘴子 AI 项目发布与源码管理固定规则

版本：2026-09-15

## 核心原则

本项目所有后续开发、升级、修复、测试、发布，统一执行以下流程：

用户侧：
- 本聊天窗口负责接收最终测试包、安装包、验收结果。
- 不要求用户自行寻找源码、构建环境或历史版本。

项目侧：
- GitHub 作为唯一长期源码和版本归档中心。
- 所有正式代码、配置、构建脚本、Workflow、安装脚本、交接文档必须同步保存。

## 每次升级必须保存

1. 完整源码
2. 前端资源
3. 后端代码
4. 构建脚本
5. 安装程序脚本
6. GitHub Actions workflow
7. 版本号文件
8. CHANGELOG
9. BUILD_STATUS
10. 交接文档
11. 功能回归清单
12. 最终安装包 Artifact 信息

## 发布流程

源码修改
→ GitHub 提交
→ Actions 构建
→ 自动测试
→ 生成安装包
→ 人工验收
→ 更新交接文档
→ 标记稳定版本

## 禁止事项

- 不允许只保存聊天记录，不保存项目资料。
- 不允许只保存 EXE，不保存源码。
- 不允许升级后丢失已有功能而没有回归记录。
- 不允许重要架构理念只存在于单个聊天窗口。

## 稳定版本管理

每个正式版本必须保留：
- commit
- tag 或 baseline 分支
- 构建记录
- 安装包记录
- 回滚方案

目标：任何未来时间，都可以从 GitHub 恢复、重新构建、继续升级。
